# Aspia update manager
Конфигуратор сервера обновлений Aspia 3.x.x.

Соответствует [официальному описанию](https://github.com/dchapyshev/aspia/blob/master/source/base/update/README.md) принципов работы сервера обновлений Aspia.
```
Attention! This is non a stable version!
```
```
Внимание! Эта версия не стабильна и предназначена только для тестирования!
```

## Возможности
### Скачивание новых релизов
 - Возможность сформировать список компонентов (DOWNLOAD_MAP) с указанием требуемых платформ и расширений инсталляторов
 - Скачивания новых релизов Aspia из [официального репозитория](https://github.com/dchapyshev/aspia) в соответствии с DOWNLOAD_MAP одной командой с проверкой уже присутствующих файлов
 - Автоматический расчет sha256 подписи для скачанного файла-инсталлятора
 - Автоматическое формирование JSON манифеста версии по скачанным файлам-инсталляторам с указанием всех необходимых реквизитов

### Управление каналами обновлений
 - Создание пустых JSON файлов для каналов обновлений или сброс сделанных ранее изменений, в случае наличия файла канала в директории-назначения, скрипт запросит перезапись
 - Указание актуальной версии обновления (с проверкой корректности)
 - Создание цепочки обновлений через добавление последовательностей (source -> target)
 - Удаление цепочек обновлений
 - Отображение цепочек обновлений в понятном виде

### Контроль и тестирование
- Реализовано самотестирование конфигурации для проверки консистентности всех файлов

### Подпись файлов (aspia_signer)
Реализован автономный (не привязанный к основной кодовой базе) Python скрипт для подписи JSON файлов полностью совместимый с командами официального [aspia_signer](https://github.com/dchapyshev/aspia/tree/master/source/tools/signer).
Файл приватного ключа генерируется в PEM формате, а публичный ключ отображается при создании приватного ключа.

#### Планируется:
 - Реализация обновления подписей при изменении JSON файлов
 - Автоматизация проверки всех подписей

## Использование:
```
./aspia_manager.py                                     # Показать справку

[Управление релизами]
./aspia_manager.py download <версия>                   # Скачать файлы, очистить лишнее и создать манифест

[Управление каналами обновлений]
./aspia_manager.py channel create <канал>              # Создать или сбросить канал (stable, beta, alpha)
./aspia_manager.py channel <канал> latest <версия>     # Установить последнюю версию для канала
./aspia_manager.py channel <канал> add <источник> <цель> # Добавить правило обновления (напр. 3.0.37 @latest)
./aspia_manager.py channel <канал> remove <источник>   # Удалить правило обновления для версии-источника
./aspia_manager.py channel <канал> list                # Показать текущую конфигурацию канала

[Проверка целостности]
./aspia_manager.py check                               # Проверить целостность всей конфигурации репозитория
```

## Параметры:
```
<канал>   - Имя канала: только "stable", "beta" или "alpha"
<версия>  - Версия Aspia в формате "3.a.b" (например: 3.1.2)
<источник>- Версия, с которой выполняется обновление (например: 3.0.37)
<цель>    - Версия назначения или метка "@latest"
```
## Примеры:
```
./aspia_manager.py download 3.1.2
./aspia_manager.py channel create stable
./aspia_manager.py channel stable latest 3.1.2
./aspia_manager.py channel stable add 3.0.37 @latest
./aspia_manager.py channel stable list
./aspia_manager.py check
```

## Настройка:
```
Откройте скрипт в текстовом редакторе и измените переменные в блоке CONFIG:
  - TARGET_ROOT_DIR     : Корневая директория сервера обновлений (здесь лежат <канал>.json и папка versions/).
  - TARGET_STORAGE_DIR  : Абсолютный путь к директории хранения инсталляторов.
  - UPDATE_BASE_URL     : Публичный URL-путь к директории storage.
  - DOWNLOAD_MAP        : Словарь, определяющий необходимые компоненты, платформы и расширения.
```

*Примечание: создано с помощью ИИ*
